# 기록으로 코스웨어를 고치는 흐름

많은 아이가 풀수록 문제가 좋아지게 하려는 장치입니다. 개인 정보는 쓰지 않고, 익명 기록만 봅니다.

## 한 번 돌리는 차례

1. 기록 내려받기: `python3 server/pull_kv.py 받은폴더` (Cloudflare 읽기 전용 토큰 필요, 설명은 파일 맨 위)
2. 문제 목록 새로 만들기(앱을 고쳤을 때만): `python3 build.py && node analysis/make_catalog.js`
3. 보고서: `python3 analysis/analyze.py 받은폴더 보고서폴더`
   - `report.md` 사람이 읽는 보고서 · `items.csv` 틀마다 한 줄 · `flags.json` 고칠 후보
4. 보고서의 '고칠 문제 후보'를 위에서부터 직접 열어 보고 고친다 → 올린다 → 다음에 다시 1번.

## 보고서가 찾는 것

| 찾는 것 | 뜻 | 고치는 방향 |
|---|---|---|
| 너무 쉬움 / 너무 어려움 | 정답률 95% 이상 / 25% 이하 | 단계를 옮기거나 수를 바꿈 |
| 잘하는 아이가 더 틀림 | 문제나 정답이 잘못됐을 가능성 | 문제를 직접 확인(가장 먼저) |
| 찍기 의심 | 가운데 시간이 1.5초보다 짧음 | 보기 자리·그림이 답을 알려 주는지 확인 |
| 오답이 오개념으로 안 잡힘 | 틀린 답의 절반 이상이 코드 없음. 많이 쓴 오답을 함께 보여 줌 | 그 오답에 오개념 코드를 붙이거나 새 코드를 만듦 |
| 아무도 안 고르는 오답 보기 | 30번 넘게 나왔는데 2%도 안 고름 | 그 보기를 실제로 하는 실수로 바꿈 |
| 조작을 거의 안 하고 냄 / 되돌리기 많음 | 무엇을 할지 모르거나 조작이 헷갈림 | 조작 화면·안내 글을 고침 |
| 다시 보이는 오개념 | 다른 날에도 같은 실수 | 도움말·조작 문제를 보강 |
| 함께 나타나는 오개념 | 한 아이에게 같이 보임 | 한쪽이 보이면 다른 쪽도 확인하는 규칙 |
| 차례 의심 | 앞 내용을 잘해도 뒤 내용 성적이 같음 | 선수 관계를 다시 봄 |

## 판단 기준

틀 하나에 응답 30건·기기 10대가 안 되면 판단하지 않습니다(`analyze.py` 맨 위의 수). 처음 몇 주는 대부분 '자료 부족'으로 나오는 것이 정상입니다. 그동안은 댓글·교실 관찰이 더 정확합니다.

## 시험

`python3 analysis/fake_data.py 가짜폴더 && python3 analysis/analyze.py 가짜폴더 보고서폴더` — 일부러 심어 둔 문제 7가지를 보고서가 찾는지 확인합니다(가짜 자료이며 실제 기록이 아님).
